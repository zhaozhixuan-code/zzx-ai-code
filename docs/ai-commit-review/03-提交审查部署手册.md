# AI 提交审查部署手册

## 第一步：准备服务器

- 系统用 Ubuntu 22.04 或 24.04。
- 安装 Python 3.10 或以上、`python3-pip`、`git`、`bash`、`curl`、`tar`、`ca-certificates`。
- Node.js `22.22.1` 和 Pi Agent `1.5.2` 由工作流安装。
- 确认服务器能访问 GitHub、依赖下载源、模型接口和飞书。

## 第二步：克隆项目，准备 Runner 用户

用 `root` 登录服务器，执行以下命令。

```bash
cd /opt
git clone https://github.com/zhaozhixuan-code/zzx-ai-code.git
cd /opt/zzx-ai-code

if ! id ai-review-runner >/dev/null 2>&1; then
  useradd --system --user-group --create-home \
    --home-dir /var/lib/ai-review-runner --shell /bin/bash ai-review-runner
fi
install -d -o ai-review-runner -g ai-review-runner -m 0750 /opt/ai-commit-review-runner
```

项目已克隆时，直接进入已有项目目录。下面用 `ai-review-runner` 运行作业，也可以沿用已有的普通账号，操作时换成该账号和它的主目录。Runner 接到作业后会自动检出项目里的 `review/` 审查脚本。

## 第三步：配置 Pi 和飞书

切换到 Runner 用户，创建配置目录。

```bash
sudo -u ai-review-runner -H bash
umask 077
mkdir -p ~/.pi/agent ~/.config/ai-commit-review
chmod 0700 ~/.pi/agent ~/.config/ai-commit-review
```

用 `vi ~/.pi/agent/models.json` 填入模型网关、API Key 和模型 ID。网关使用 `/v1/responses` 时，填 `openai-responses`。使用 `/v1/chat/completions` 时，填 `openai-completions`。

```json
{
  "providers": {
    "review-gateway": {
      "baseUrl": "https://gateway.example.com/v1",
      "api": "openai-responses",
      "apiKey": "填实际 API Key",
      "models": [{ "id": "填实际模型 ID" }]
    }
  }
}
```

用 `vi ~/.pi/agent/settings.json` 选择上面注册的模型。

```json
{
  "defaultProvider": "review-gateway",
  "defaultModel": "填与 models.json 一致的模型 ID"
}
```

打开要收消息的飞书群，添加**自定义机器人**并启用**签名校验**。已有机器人可直接沿用。用 `vi ~/.config/ai-commit-review/feishu.json` 填入配置。

```json
{
  "webhook_url": "填完整的飞书机器人 Webhook",
  "signing_secret": "填签名密钥",
  "target_name": "填群名"
}
```

换服务器时，可直接迁移旧机 Runner 的 `settings.json`、`models.json`、已有的 `auth.json` 和 `feishu.json`。旧机设置过 `PI_CODING_AGENT_DIR` 时，从该目录取 Pi 配置。复制到上面的对应目录后，文件归 Runner 用户所有，权限设为 `0600`。自定义网关原来用环境变量取 Key 时，可以直接把新机 `models.json` 的 `apiKey` 填为实际值。机器人开了 IP 白名单时，把新机的出站公网 IP 加进去。

## 第四步：注册 Runner

1. 打开 GitHub 仓库的 **Settings → Actions → Runners → New self-hosted runner**，选择 **Linux** 和服务器架构。
2. 在上一步的 Runner 用户终端运行 `cd /opt/ai-commit-review-runner`，按 GitHub 页面 **Download** 部分执行下载、校验和解压命令。
3. 复制页面 **Configure** 命令里的 `--token` 参数值。运行下面的命令，提示输入时粘贴令牌。换服务器时给新 Runner 取一个与旧 Runner 不同的名字。

   ```bash
   read -r -s -p '输入 Runner 注册令牌: ' runner_token
   printf '\n'
   ./config.sh --unattended \
     --url https://github.com/zhaozhixuan-code/zzx-ai-code \
     --token "$runner_token" \
     --name zzx-ai-review-new \
     --labels ai-commit-review \
     --no-default-labels
   unset runner_token
   ```

4. 注册成功后执行 `exit` 回到 `root` 终端，然后安装服务。

   ```bash
   cd /opt/ai-commit-review-runner
   ./svc.sh install ai-review-runner
   ```

## 第五步：启动 Runner，打开审查开关

换服务器时，等旧 Runner 空闲，在**旧机**的 Runner 安装目录执行 `./svc.sh stop`。然后在**新机**用 `root` 执行以下命令。

```bash
cd /opt/ai-commit-review-runner
./svc.sh start
./svc.sh status
```

打开 GitHub 仓库的 **Settings → Actions → Runners**，确认新 Runner 在线且带 `ai-commit-review` 标签。再打开 **Settings → Secrets and variables → Actions → Variables**，确认以下三个仓库变量均为 `true`。

- `AI_REVIEW_RUN_MODEL`
- `AI_REVIEW_MASTER_ENABLED`
- `AI_REVIEW_SEND_FEISHU`

## 第六步：试跑并验收

1. 在项目目录查找一条有源码改动的提交，复制完整 SHA。

   ```bash
   cd /opt/zzx-ai-code
   git log -10 --format='%H %s' -- src/main/java
   ```

2. 打开 GitHub **Actions → AI commit review → Run workflow**。选 `master`，将 SHA 填进 `commit`，勾选 `send_feishu`，点击运行。
3. 打开作业的 **Review commits and send the Feishu summary** 步骤。确认新 Runner 接单、提交为 `completed`、飞书为 `sent` 且 `business_code` 为 `0`。群里应收到一条简短摘要，Actions 运行的报告归档数应为 `0`。
4. 下一次推送到 `master` 时，确认审查自动触发且群里收到摘要。迁移验收通过后，可在 GitHub **Runners** 页面移除旧 Runner。需要回退时，先停新 Runner，再启动旧 Runner。
