# 质量检查与自动修复运行验收说明

适用范围：根目录单体后端与 Vue 前端，分支 `codex/real-quality-check-auto-fix`。2026-11-18 代码交付，完整环境验收仍待完成；微服务未修改。

## 运行准备

1. 管理员先执行 `sql/quality_check.sql` 创建 `quality_task`、`quality_round`。应用不自动建表，质量功能默认开启，启动时会扫描本实例遗留任务；缺表会导致初始化失败。本次未执行用户数据库迁移。
2. 使用 Java 21，准备项目原有 MySQL、Redis 与模型配置。密钥只放环境或本地私有配置，不写入报告、截图说明或提交。
3. Docker CLI 必须能访问可用的 Linux 容器引擎。管理员预装固定镜像 `node:22.16.0-bookworm-slim`，例如执行 `docker pull node:22.16.0-bookworm-slim`；任务运行始终 `--pull=never`，不会自动拉取，也不会回退宿主机执行生成工程。
4. Linux 上让后端进程和配置的容器 UID:GID 对任务源码目录具有必要写权限。默认 `1000:1000`，可用 `QUALITY_BUILD_USER` 调整为实际非 root 身份；不能使用 UID 或 GID 0。不要用开放全部目录权限的方式替代正确的身份配置。
5. 安装依赖阶段默认网络 `bridge`，禁用 npm 生命周期脚本；生产应由管理员预先配置限制出口的专用 Docker 网络，再设置 `QUALITY_INSTALL_NETWORK`。构建阶段固定 `network=none`、非 root、只读根文件系统、禁特权及 CPU/内存/PID 限额。执行固定 Vite CLI，不执行模型提供的 build 脚本；Vite 配置和依赖仍属于不可信内容，Docker 限制不等同于独立虚拟机。
6. 安装 Chrome 与匹配 ChromeDriver，按现有 screenshot 配置提供驱动；测试可用 `-Dwebdriver.chrome.driver=绝对路径`。质量检查强制保留 Chrome 自身沙盒，不能通过 `--no-sandbox` 解决部署问题。浏览器需能访问服务端临时 loopback 端口。
7. 当前互斥是单 JVM 锁，使用单实例部署与稳定的 `QUALITY_INSTANCE_ID`，不支持多实例共同写同一应用目录。任务目录与已发布指针需要持久保存。

官方行为依据：[Docker run](https://docs.docker.com/reference/cli/docker/container/run/)、[Docker bind mount](https://docs.docker.com/engine/storage/bind-mounts/)、[npm install ignore-scripts](https://docs.npmjs.com/cli/v10/commands/npm-install#ignore-scripts)、[Selenium Chrome](https://www.selenium.dev/documentation/webdriver/browsers/chrome/)。项目约束和实际验证结果以开发跟踪文档为准。

## 配置与运行语义

根 `src/main/resources/application.yml` 的 `app.quality` 支持以下环境变量：

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `QUALITY_CHECK_ENABLED` | `true` | 关闭后 Vue 生成明确不可用；不恢复宿主机构建。HTML、多文件保留既有路径 |
| `QUALITY_INSTANCE_ID` | `local` | 标记本进程任务归属；同一标识不能同时运行多个进程 |
| `QUALITY_BUILD_IMAGE` | `node:22.16.0-bookworm-slim` | 管理员预装固定镜像 |
| `QUALITY_BUILD_USER` | `1000:1000` | 非 root UID:GID |
| `QUALITY_INSTALL_NETWORK` | `bridge` | 管理员预设安装网络 |
| `QUALITY_MAX_REPAIR_ATTEMPTS` | `2` | 默认最多三次检查；设为 0 时只检查 |
| `QUALITY_MAX_MODEL_TOOL_ROUNDS` | `50` | 单模型阶段工具循环预算，独立于修复次数 |
| `QUALITY_OVERALL_TIMEOUT` | `30m` | 整体期限 |
| `QUALITY_MODEL_TIMEOUT` | `3m` | 生成/修复模型阶段期限 |
| `QUALITY_BUILD_TIMEOUT` | `10m` | 单次构建期限 |
| `QUALITY_BROWSER_TIMEOUT` | `2m` | 浏览器阶段期限 |

本轮所有必选检查通过，且产物确认、模型上下文和报告保存成功后，才能发送成功终态。代码类失败进入受限修复；环境异常不交给模型改源码。无源码变更、诊断无进展、预算耗尽、期限到达均提前结束。

任务位于代码输出根下 `.quality/apps/{appId}/tasks/{taskId}/source`。每轮构建写唯一 `quality-dist-{round}`，通过后确认成 `dist`；应用 `published` 文本指针原子切换。公开预览 URL 仍为 `/api/static/vue_project_{appId}/dist/index.html`，内部源码、任务目录、日志不通过公开预览返回。失败任务保留，上一成功预览继续可用；部署、下载只读取已确认结果并持同一应用锁。

质量报告：`GET /api/app/quality/report?appId=...&taskId=...`，省略 taskId 返回最近任务。证据：`GET /api/app/quality/evidence?appId=...&taskId=...&ref=...`。两者只向应用所有者开放；ref 使用报告中的固定文件名。日志有界，截图保留用于检查，不代表页面业务语义或美观达标。

SSE：普通模型事件维持原有正文协议，命名 `quality` 发送任务快照，`business-error` 表示失败，`done` 仅表示成功。前端失败保留旧 iframe，成功才刷新版本；连接错误关闭 EventSource，不自动重新提交生成任务。主动取消和断连会传播到模型、进程及浏览器，迟到事件不能发布失败产物。

## 定向复核命令

以下从仓库根目录执行；Java 路径和驱动路径替换为本机实际值。无需启动用户业务服务或迁移数据库即可执行隔离测试，不运行全量外部集成测试。

| 测试类与开关 | 验证内容 | 本次结果 |

## 未完成验收与故障处理

- 本机 Docker Desktop/WSL 失败：日志出现 WSL 枚举退出 `0xc000012d`，随后 dockerInference 监听文件不可访问；daemon 返回 500 或 Linux engine pipe 不存在。没有重置或删除 Docker/WSL 数据。真实 Vue 构建、编译故障与模型修复组合需在引擎可用后执行；当前不能标记 M1/M2 整体验收完成。
- 实际依赖中 selenium-java 声明 4.33.0，部分核心组件由 BOM 选为 4.31.0。Chrome 157 没有匹配的版本化 DevTools 实现，通用 CDP 命令已实测可用；升级浏览器/依赖仍需复核。PATH 中旧 146 驱动曾实际启动失败。
- 浏览器只检查受控首屏：错误、关键本地 JS/CSS、疑似空白及截图。外部网络被阻断，未覆盖远程 API、全部点击、路由、产品需求语义或全面安全审计。真实用户数据库、实际部署和生产流量未验收。
- 重启只将同 instance-id 的 RUNNING 标记 INTERRUPTED，不自动续跑。重启前须确认旧容器/浏览器已退出；不能靠重启绕过遗留进程检查。清理状态不明时应用锁保留，需要管理员先定位该 taskId 的容器/进程并确认退出，再安排服务恢复；当前没有自动解锁入口。
- 数据库事务只能覆盖任务/轮次记录；文件指针、Redis 上下文与数据库之间采用补偿，不能提供跨资源原子提交。进程崩溃窗口仍可能造成指针、上下文、报告不同步，需结合 published、任务 UUID 和报告人工核对；不要自动重放模型文件工具。
- 失败任务、日志、截图保留在原目录，没有定时清理。本次未删除目录、未执行数据库迁移、未自动部署、未推送分支。
